# Self-Verification Gate (SVG)

> **판정 기준**만 정의한다. 절차는 superpowers skill, 심각도는 `common/code-review.md`,
> 단계별 매핑은 `code-development-principles.md` §0-2가 소유한다.

## 원칙 4개

1. **작성자 ≠ 검증자.** 같은 컨텍스트에서 작성과 판정을 함께 하지 않는다. 판정은 별도 agent에 위임한다(매핑은 `AGENTS.md`).
2. **증거 수집은 메인이 직접.** 검증 명령을 이 턴에 실제 실행하고 출력을 읽는다 — 남이 돌린 결과를 내 증거로 쓰지 않는다. **판정만** 위임한다. 증거 없는 판정은 무효다.

   **"직접 확인"의 범위는 명령 출력만이 아니다.** 구현된 **코드**·**설계서**·**테스트 결과**·**렌더된 화면**을 내가 열어서 본다. 다른 agent·다른 세션·이전 턴의 나가 "했다"고 답한 것은 **증거가 아니다** — 그 말이 가리키는 산출물을 직접 열어야 증거다. 화면이 대상이면 스크린샷을 떠서 **이미지를 실제로 본다**(격리 프로필 헤드리스로 남의 브라우저 세션을 건드리지 않는다).

   ⚠️ **눈 검사를 사용자에게 넘기지 않는다.** "열어서 확인해줘"는 검증의 위임이 아니라 **누락**이다. 내가 볼 수 없는 진짜 이유가 있으면 그 이유와 **대신 확보한 증거**를 함께 밝히고, 못 본 항목을 미검증으로 남긴다 — 통과로 적지 않는다.
3. **메인 응답에 검증 테이블(항목|판정|증거)을 직접 쓰지 않는다.** 그것은 위임받은 agent의 산출물이다.
4. **피드백은 기술적으로 검증한 뒤 수용/반박한다** (`superpowers:receiving-code-review`). 형식적 동의 금지.

## 언제 위임하는가

| 대상 | 역할 · 모델 | 기준 |
|---|---|---|
| **코드 작성·수정 완료** | code-reviewer · opus (`ReportFindings`) | V1~V5 + T0~T5 |
| **되돌리기 어려운 결론** (설계 확정, 스키마·계약 변경, 캡틴에게 올리는 판단) | critic · opus — 반증을 시도시킨다 | A1~A5 / D1~D5 + 4 Lenses |
| 보안 민감 코드 | `/security-review` skill | `common/code-review.md` |

**위임하지 않는 것**: 도구 실행·설정 작업·상태 확인·코드 설명·잡담·후속 실행 지시, 그리고 되돌리기 쉬운 소규모 판단. 게이트를 모든 문장에 걸지 않는다.

**Critic 판정**: `PASS` 결론 제시 가능 / `CHALLENGE` 보완 후 재검증 / `REJECT` 폐기 후 재분석.

## 체크리스트 (위임 프롬프트에 항목을 명시한다)

`code-development-principles.md`가 단계별로 이 코드를 참조한다 — 코드를 바꾸면 그쪽도 고친다.

**ANALYSIS** — A1 증거 출처(`파일:줄`·로그·쿼리) · A2 직접 확인(Read/Grep/Bash) · A3 대안 가설 1개+ · A4 복수 출처 일치 · A5 확신도(CONFIRMED/LIKELY/UNCERTAIN)

**DESIGN** — D1 검증된 분석 기반 · D2 영향 범위(참조 추적) · D3 4 Lenses 전체 · D4 현재 코드와 충돌 여부 · D5 이 설계의 약점 1개+

**DEVELOPMENT** — V1 확정 설계 기반 · V2 방어 로직(null/빈값/예외) · V3 컨벤션(매직넘버·naive datetime 금지) · V4 의존성·주입 · V5 lint + 타입 오류 0

**TEST** — T0 red→green(구현 전 실패를 실제로 관측. **부재를 단정하는 테스트는 red 증거가 아니다** — "N건 중 M건이 red"로 센다) · T1 변경 소스 커버 · T2 경계값·null·empty · T3 예외·장애 · T4 무회귀(기존 passed 수 유지/증가) · T5 실행 출력 첨부
